# Hook 派发机制

> 状态：当前整体原型采用同步检查点派发，伤害反应使用 FIFO 队列；完整战斗契约与通用优先级仍待讨论。

本机制负责“向哪些有效 Model 调用哪个公共方法”。具体业务系统负责确定调用时机；命中判定、伤害公式、Buff 生命周期等规则不由派发器决定。

## 参与者与调用

整体原型通过 Unit 获取 Buff 与技能快照，在调用前检查实例仍然有效。集合管理与方法派发分离，不使用通用注册表或事件总线。冷却中的技能不会仅因冷却而失去所有公共 Hook 的参与资格。

[ADR-006](../Decisions/ADR-006-Hook统一派发与Model自主判断.md) 已确定 MVP 的目标规则：公共战斗 Hook 向当前战斗内的有效 Model 统一派发，由 Model 在具体 Hook 内判断是否产生效果；Owner 不限定关注对象。该规则同时适用于通知和阶段允许的干预，不要求广播专属实例生命周期入口。当前原型仍混合使用局部与全场派发，尚待按此决策迁移，不能将目标规则视为已实现。

快照与有效性检查的当前细节、同步异常及已完成变更的行为，见 [Hook 派发实现记录](../../Implementation/Prototype/Hook派发实现.md)。独立伤害演示使用静态 Model 列表，不能当作动态增删参与者已经完整验证。

## 规则依据

- 一次伤害的阶段设计：[ADR-005：伤害结算流程](../Decisions/ADR-005-伤害结算流程.md)；当前原型的 Hook 清单、顺序与上下文见 [伤害结算实现](../../Implementation/Prototype/伤害结算实现.md)。
- 完整战斗与回合时机：[ADR-004](../Decisions/ADR-004-战斗流程中的Hook.md)，仍为草案。
- 使用公共虚方法与内容内聚的架构方向：[ADR-001](../Decisions/ADR-001-选择Hook与Model架构.md)。
- 公共 Hook 的统一参与范围与内容条件：[ADR-006](../Decisions/ADR-006-Hook统一派发与Model自主判断.md)，已确定、待实现。

伤害阶段权限和显式否定/替换按 ADR-005 执行，直接嵌套伤害改由反应队列处理。公共 Hook 的候选范围按 ADR-006，具体业务时机、死亡后的监听资格与通用优先级仍需补充，不能从当前遍历顺序推导数学规则顺序。
