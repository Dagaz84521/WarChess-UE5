# 寻路算法确定

> 编号：ADR-010
>
> 状态：已确定
>
> 创建日期：2026-11-03
>
> 决策日期：2026-11-03
>
> 替代 [ADR-009](ADR-009-MVP单位费用移动采用BFS.md) 的 BFS 选型；细化 [ADR-007](ADR-007-移动系统与寻路算法解耦.md) 中 Dijkstra 的优先队列实现。

## 1. 背景

移动范围需要保存预算内所有可达格的最低行动力消耗和前驱，供范围展示与多目标路径恢复共享。默认移动规则每步为 1，但 [基础战斗规则 402-3](../../Rules/基础战斗规则.md#402-3-领域控制与费用免除) 已规定 ZOC 会产生额外移动消耗，不能将正式搜索长期限制为单位费用。

实际移动预算通常仅十几点，费用以整数表达。需要兼顾带权最短路的正确性、可预测的处理顺序和较小的实现规模。

## 2. 面临的问题

如何在小整数预算范围内，支持非负整数边费用并生成完整最短路径树，同时减少通用堆操作？

## 3. 候选方案

| 方案 | 适用条件与特点 | 本次取舍 |
| --- | --- | --- |
| 普通 BFS | 等费用时最少步数等于最低消耗 | 无法直接覆盖 ZOC 附加费用，不采用 |
| 普通 FIFO 加反复松弛 | 能修正先前距离，但节点可能反复扩展 | 不采用作为正式调度方式 |
| 二叉堆 Dijkstra | 按最低累计费用处理，支持非负权重 | 正确且通用，暂不使用其堆结构 |
| 预算桶式 Dijkstra | 累计费用作为桶下标，从小到大处理 | 采用 |

松弛不是独立于 Dijkstra 的替代算法。正式方案仍使用松弛，桶承担最小优先队列职责。

## 4. 最终决定

### 4.1 算法与容器

使用预算截断的桶式 Dijkstra，可视为适用于当前预算范围的 Dial 类实现：分配 `Budget + 1` 个桶，桶 i 保存当前已知累计消耗为 i 的候选格。从 0 到 Budget 顺序扫描，桶内使用 TArray 加递增读下标实现 FIFO。

初始化起点费用为 0，无前驱。展开一格后，对每条边计算候选费用；仅在严格改善时更新 CostMap、PreviousMap 并加入对应桶。等费用保留已有前驱，稳定邻接顺序决定等价路径选择。

费用改善后不主动删除旧桶条目。读取节点时，如果当前桶下标不等于 CostMap 中最新费用，跳过该过期条目。不能在第一次入桶时将节点永久标记为完成。

### 4.2 费用、预算与错误

- Cost 使用 int32 非负整数；0、1、2 等均可接受，负费用返回 InvalidEdgeCost。
- 先判断 `EdgeCost > Budget - CurrentCost`；超预算直接跳过，再执行安全加法。极大但非负的边费用是不可负担的转移，不因相加产生溢出。
- 预算边界的节点仍查询出边，以支持零费用转移。当前桶的新条目继续处理，零预算也可生成完整零费用可达闭包。
- 仅严格改善时更新前驱，避免零费用环引起重复处理和前驱环。
- 当前直接桶数组支持预算 0～4096，由 `FPathFinding::MaxSupportedBudget` 定义。此上界用于防止误传极大预算造成大量分配，不是游戏平衡设定；负值或超上界返回 InvalidBudget。
- 任何失败都清空输出结果，不暴露部分树。调用方继续负责校验单位与起点，搜索期间图和单位输入保持不变。

### 4.3 接口与职责

保留 `FPathFinding::SearchRange`、`FMoveRangeResult.Start / CostMap / PreviousMap`，以及 GetMoveRange、GetCost、BuildPath。查询与路径恢复不触发新的搜索，不修改占位或扣除行动力。

Board 提供事实，MoveRule 解释合法转移和费用，PathFinding 只处理邻接回调提供的图。ZOC 如何按进入、离开或重叠控制加费仍由规则确定，本决策不实现 ZOC。

若未来规则依赖路径历史，例如只对首次穿越加费，需要扩展搜索节点状态；不能仅靠替换优先队列解决。

## 5. 决策理由与复杂度

非负费用保证处理桶 i 时不会产生下标小于 i 的新候选，因此仍满足 Dijkstra 的按最低累计费用处理原则。相较普通 FIFO 反复修正，它具有明确的费用处理顺序。

令 V、E 为预算内涉及的节点和出边，B 为预算。在字典平均常数时间查询假设下，直接扫描预算桶的开销为 O(V+E+B)。严格改善的入桶次数受边检查数约束；零费用也不改变该结论。

懒删除方案可能保存旧条目，空间为 O(V+E+B)，并非只有 B 个空间。六邻接棋盘 E ≤ 6V，因而可写为 O(V+B)。没有性能实测前，不承诺它比 BFS 或堆式 Dijkstra 快多少。

## 6. 代价与影响

仅支持整数费用。预算变得很大时，扫描/分配 B 个桶可能不合适，届时重新评估堆或其他优先队列；本版不增加自动算法切换、循环桶或复杂删除结构。

ADR-009 保留历史并标记被替代。现有单位费用 JSON 场景继续有效，输出 searchAlgorithm 更新为 Bucket Dijkstra，Python 绘图继续只展示真实 C++ 结果。其校验仍针对该固定费用样例，不代表已经实现带权 JSON 地形导入。
