# ADR-002：采用 Code-First 开发方式

> 状态：已确定
>
> 本记录确认开发方式，不表示内容接口已确定或代码已实现。

## 1. 背景

项目使用 Unreal Engine 和 C++，当前优先完成最小可运行 MVP。战斗规则和核心概念仍在设计，复杂可视化技能编辑器不在当前范围内。

## 2. 面临的问题

需要决定初期如何定义和扩展游戏规则，以及是否同时建设复杂的可视化数据驱动编辑体系。

## 3. 候选方案

- Code-First：优先通过 C++ 定义游戏规则。
- 优先建立复杂的可视化数据驱动体系，再通过该体系配置规则。
- 代码与数据混合：规则由代码承载，部分参数通过数据配置；具体边界仍需另行讨论。

候选方案用于说明选择空间，不表示其实现成本或效果已经通过对比实验确认。

## 4. 最终决定

采用 Code-First，优先通过 C++ 定义游戏规则，初期不建立复杂的可视化数据驱动编辑体系。

本决策不要求所有参数硬编码，也不确定未来的数据配置方式；相关边界保留为后续议题。

## 5. 决策理由

使初期工作聚焦规则职责、协作契约和 MVP，避免在规则尚未明确时同步设计复杂编辑体系。这符合当前技术环境和行为内聚的目标；不据此宣称已经获得开发效率或性能收益。

## 6. 代价与影响

预期规则变更需要 C++ 开发能力并遵循代码构建流程；内容开发者需要理解扩展契约。可供非程序开发者配置的能力在初期受限，未来引入数据配置时需要重新明确代码与数据的边界。

这些影响尚需在实际内容开发中验证，不预设具体编辑工具、数据格式或类实现。
