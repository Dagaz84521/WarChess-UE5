# ADR-009：MVP 单位费用移动采用 BFS

> 状态：已被替代
>
> 2026-11-03：由 [ADR-010：寻路算法确定](ADR-010-寻路算法确定.md) 替代，正式搜索采用预算桶式 Dijkstra，以支持 ZOC 等非负整数附加费用。下文保留历史决策。
>
> 创建日期：2026-11-03
>
> 决策日期：2026-11-03

## 1. 背景

当前 UE MVP 的 `FMoveRule` 每次进入邻居固定消耗 1，暂不支持带权地形、零费用移动。现有范围搜索采用 Dijkstra，用户希望收敛实现为 BFS，并了解两者差距。

本决策替换 [ADR-007](ADR-007-移动系统与寻路算法解耦.md) 中当前 UE MVP 的算法选型；保留规则与搜索解耦、一次生成完整范围树、范围及路径共享结果的设计。历史 TypeScript 原型不在本次修改范围。

## 2. 面临的问题

在每步费用固定为 1 的前提下，如何用较简单的实现生成预算内所有格子的最短步数及前驱，同时避免未来带权规则被误用？

## 3. 候选方案

| 方案 | 适用条件 | 搜索开销 | 本次取舍 |
| --- | --- | --- | --- |
| FIFO BFS | 所有边费用均为 1，预算按步数计算 | O(V+E)，每格首次入队时确定距离 | 采用 |
| 最小堆 Dijkstra | 非负费用可不同 | 常见实现 O((V+E) log V)；懒删除实现按堆条目计 | 保留为以后带权需求的重新选型方向 |

六邻接棋盘 E 不超过 6V。两者在固定费用下得到相同最低消耗；稳定邻接顺序下，本次实现也保持同一等长路径的前驱选择。复杂度描述不替代本机实测，实际查询仍包含 Board 访问和结果分配。

## 4. 最终决定

- 正式搜索仅使用 BFS。TArray 加递增读下标实现 FIFO，不从数组头部反复删除。
- 保持 `SearchRange` 和 `FMoveRangeResult` 的数据接口。CostMap 的累计消耗就是最少步数，PreviousMap 在首次入队时写入。
- 起点消耗为 0，无前驱。包含预算边界；边界节点不查询出边。零预算只返回起点。
- 只接受 `FMoveNeighbor.Cost == 1`。在实际展开时发现负数、0、2 或其他非 1 值，返回 `InvalidEdgeCost` 并清空结果，不静默忽略费用或自动切换算法。
- 保留 `InvalidBudget`。删除不再会产生的 `CostOverflow`：只有 Cost < Budget 时才生成 Cost+1，而 Budget 不超过 int32 上限。
- 起点与单位有效性仍由上层校验；搜索仍不修改 Board，不扣行动力。
- `FMoveRule` 仍可继承。派生规则若改变费用，应重新选择支持对应费用的搜索算法，不能直接接入当前 BFS。

## 5. 决策理由

MVP 的最少步数即最低行动力消耗，FIFO 即可保证正确性，无需维护最小堆、重复松弛或处理过期堆条目。明确拒绝非单位费用，使未来规则扩展时能够暴露契约不匹配。

## 6. 代价与影响

当前不支持零费用边或带权地形。增加这类玩法时必须重新评估算法，不能只改 MoveRule。GetMoveRange、GetCost、BuildPath 及 JSON 结果结构继续使用；输出新增 `searchAlgorithm = BFS`，图像标题读取该元数据。

旧 ADR 和架构图保留历史内容，并标注本次算法调整。带权示例仅供未来设计参考，不表示当前 C++ 搜索支持它们。

## 7. 实现与验证

[代码与接口](../../Implementation/Movement/PathFinding实现.md)、[JSON 场景](../../../../Tests/Fixtures/Movement/README.md)。

- 测试覆盖最少步数、稳定平局、普通环、预算边界、零预算、非 1 费用拒绝、无部分结果和真实 Board 接入。
- 对已有 JSON 场景比较改动前后：格子集合、累计消耗与前驱及选定路径应一致。
- `WarChess.Performance.PathFindingComparison` 使用真实 Board+MoveRule，在 61、817、3169 格开放棋盘比较结果及耗时；5 批次交替执行，报告每批平均耗时的中位数，不断言性能阈值。
- 旧堆搜索仅存在于自动化测试中。对比包含结果分配/释放；新版 BFS 会跳过预算边界的出边查询，旧基准保持原行为。数据属于本机 Development Editor 测量，不代表所有硬件或 Shipping 构建。
- 本轮实际结果见实现记录。

重新评估条件：地形、能力或 ZOC 开始改变步进费用，或者出现依赖路径历史的移动限制。只有可达边变化、每步仍为 1 时，BFS 仍适用。
