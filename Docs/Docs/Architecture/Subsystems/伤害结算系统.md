# 伤害结算系统

> 状态：整体原型已按 ADR-005 接入四阶段、两种公式、概率判定、统一乘数、否定/替换、死亡通知与反应队列；护盾等扩展仍待设计。

## 职责

处理一次已确认的伤害请求，协调暴击与格挡判定，确定基础公式输入，执行伤害修正和生命结算，并输出结果与相关通知。命中与段数由技能层负责。

CauseDamage 支持 Direct 与 PercentMaxHealth：前者使用威力、指定攻防属性及乘数，后者读取当前最大生命与比例。两者共用施加出口，统一处理否定、治疗替换、取整、实际扣血、溢出和死亡。Fixed 仅作预留，当前明确拒绝旧请求。

## 核心对象与状态归属

| 对象或数据 | 职责 |
| --- | --- |
| DamageCmd | 一次伤害的统一执行入口，负责规则推进和状态写入。 |
| 伤害上下文 | 保存不可变请求、阶段输入、已完成判定与后续命令提交能力；阶段结束后冻结。 |
| 伤害结果 | 区分基础伤害、最终待扣伤害、实际扣血及生命变化。 |

伤害公式、两类伤害的关系及阶段边界以已确定的 [ADR-005：伤害结算流程](../Decisions/ADR-005-伤害结算流程.md)为准，归档的 [Codex 讨论版](../Archive/Decisions/ADR-005-伤害结算流程-Codex版.md)仅供历史对照。当前原型接口、验证及未决项的暂定行为见 [伤害结算实现](../../Implementation/Prototype/伤害结算实现.md)。此处仅记录系统分工。

## 与其他系统的边界

- [属性系统](单位系统.md#属性)维护属性；伤害结算读取属性、提交扣血，不拥有第二份 Health。
- [技能](单位系统.md#技能)、[Buff](单位系统.md#buff)提出伤害或提交修正，DamageCmd 不按具体技能、Buff 名称编写分支。
- [Hook 机制](../Mechanisms/Hook派发机制.md)负责发现和调用参与者，不决定伤害公式。
- [战斗流程](战斗流程系统.md)处理行动资格和胜负推进，不重复实现单次扣血。

## 当前范围与后续边界

整体原型的检查点、概率属性、阶段权限、队列及真实扣血见 [伤害结算实现](../../Implementation/Prototype/伤害结算实现.md)。独立 [DamagePrototype](../../../DamagePrototype/README.md) 保留历史逐条记录演示，本次未迁移。

护盾、分摊、复活、通用优先级、持久化回放和治疗专用 Hook 仍待设计。最小 HealingCmd 独立执行治疗，不代表所有资源变更都复用伤害契约。
