# 单位系统

> 状态：Unit、属性、Buff、技能的最小逻辑组成已有原型；完整战斗集成与 UE 对象生命周期仍待确定。

## 职责与组成

单位系统管理一个单位拥有的状态与内容。Unit 组合 AttributeSet、BuffSet、SkillSet，分别保存属性、当前效果和技能；属性、Buff、技能的系统设计统一记录在本文。

| 对象 | 职责与状态归属 |
| --- | --- |
| Unit | 三个 Set 的逻辑归属与访问，以及原型中的 Model 快照和有效性查询。 |
| AttributeSet | 本单位的属性与修饰器集合。 |
| BuffSet | 本单位当前拥有的 Buff 实例。 |
| SkillSet | 本单位当前拥有的技能实例。 |

各对象保留自己的职责，具体内容行为写在对应 Model 中。这是逻辑组成关系，尚未确定 UObject、Actor、组件、成员指针类型或物理代码模块。

## 属性

属性部分负责属性存储与查询、修改基础值、添加与移除修饰器，以及维护计算后的当前值。

| 对象 | 职责 |
| --- | --- |
| AttributeSet | 注册和查找本单位拥有的属性，提供集合访问入口。 |
| Attribute | 保存 BaseValue、Modifiers，维护只读 CurrentValue。 |
| Modifier / Handle | 表达一次属性修正及其独立身份，支持来源精确清理。 |

属性计算和 Health 的语义以 [ADR-003](../Decisions/ADR-003-Buff改变Attribute的方式.md) 为准。PrototypeAttributeSet 包含 Health、MaxHealth、AttackPower、DefendPower，以及 CritChance / CritMultiplier / BlockChance / BlockMultiplier；Health 不接 Modifier，生命上限增益放在 MaxHealth。概率增加百分点使用 Flat 修正。

Buff 可以创建、追踪并移除自己的 Modifier；属性部分不决定 Buff 的持续时间或叠层。伤害结算读取攻防属性并提交扣血，命中、暴击、伤害公式和击杀通知不由属性对象执行。

ResourceAttribute 是否统一生命、行动力和蓝量仍未决定；最大生命变化后的裁剪、UE GameplayTag 与 Handle 映射也待明确。

## Buff

Buff 部分管理单位当前持有的状态效果，支持施加、叠层、持续与移除。增益、减益与永久被动均可以由 BuffModel 表达。

| 对象 | 职责 |
| --- | --- |
| BuffSet | 持有、查找和遍历当前 Buff 实例。 |
| BuffModel | 保存自身状态，定义效果、生命周期回调与公共 Hook 响应。 |
| BuffCmd | 统一执行施加、增减层、扣时间和移除，并发出对应规则通知。 |

Buff 自己定义触发条件，通过 BuffCmd 请求状态变更；集合不承担每种效果的玩法逻辑。它追踪并清理自己创建的 Modifier，不干预其他效果的项。

战斗流程派发回合阶段，Buff 决定是否结算或请求扣时间。技能可以请求 BuffCmd 施加效果，不重复实现合并、层数或移除处理。伤害阶段与权限以 [ADR-005](../Decisions/ADR-005-伤害结算流程.md) 为准，原型已接入的时机与未决扩展约定见 [伤害结算实现](../../Implementation/Prototype/伤害结算实现.md)；Buff 不复制整套伤害计算。

同标识合并、层数、刷新时间、永久效果、生命周期清理等当前契约保留在实现记录中。一次性效果的消耗反馈、嵌套状态变更、失效处理和完整死亡清理仍需结合战斗规则明确。

## 技能

技能部分管理单位拥有的技能和各技能自身状态，以 OnPlay 定义效果，通过命令请求伤害、Buff 等系统执行具体变更。

| 对象或入口 | 职责 |
| --- | --- |
| SkillSet | 添加、按标识查找、移除和遍历本单位技能。 |
| SkillModel | 定义 OnPlay、保存自身冷却并响应公共 Hook。 |
| Play | 执行当前技能层面的释放检查，再调用 OnPlay。 |

SkillSet 不按技能名称集中实现效果。技能的 Owner 与持有关系需保持一致；技能可用也不代表单位仍有行动机会，行动资格由战斗流程检查。

当前原型的 SkillHitExecutor 在技能层确认命中段、处理多段中断和目标顺序，再提交 Direct 或 PercentMaxHealth 请求；普通技能用 Power 表达威力，百分比用 Ratio 表达比例。两者共用 CauseDamage 施加出口，规则以 [ADR-005](../Decisions/ADR-005-伤害结算流程.md) 为准，具体行为见 [伤害结算实现](../../Implementation/Prototype/伤害结算实现.md)。Fixed 仍为预留。技能仍可包含冷却、目标或附加 Buff，也不要求所有技能都造成伤害。

当前原型支持最小释放入口、成功后进入冷却、回合冷却推进和具体技能扩展。OnPlay 是技能自身入口，公共 Hook 仍放在 AbstractModel。多目标通用契约、目标合法性、资源消耗、完整释放阶段与失败处理尚待确定；Action 是否独立存在也未决定。

## 当前范围与待定事项

当前原型已连接三个 Set，并验证不同单位的属性、Buff 和技能状态隔离。Unit 不按具体效果名称增加玩法分支。

后续需明确单位及内容的初始化与释放顺序、跨单位引用有效期、死亡后的清理，以及资源与完整行动规则。“Health 为 0”不自动表示所有相关对象已经销毁。
