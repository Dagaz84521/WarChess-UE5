# 战斗流程系统

> 状态：1v1 与 2v2 流程已有验证原型；完整回合与行动统一规则待设计。

## 职责

持有战斗阶段与参与单位，管理全局回合、单位行动资格、阶段推进和胜负判定。负责在约定位置调用各系统，而不是集中实现所有技能与 Buff 效果。

## 核心对象与状态归属

| 对象或概念 | 职责 |
| --- | --- |
| CombatManager | 当前原型中执行全局回合结束派发。 |
| 对战流程控制器 | 管理行动方、可用单位、操作提交与阶段推进。 |
| 全局回合 | 所有参与单位完成一轮行动的战斗周期。 |
| 单位行动资格 | 表示单位在当前规则下是否还有行动机会。 |

上述是逻辑职责，不要求新增独立 Action 类。完整战斗阶段与公共时机仍由 [ADR-004](../Decisions/ADR-004-战斗流程中的Hook.md) 后续记录，不在此补写未确认的时序。

## 与其他系统的边界

- [单位系统](单位系统.md)提供参与对象；流程决定行动资格，不复制单位的技能和属性状态。
- [技能](单位系统.md#技能)负责具体效果，流程在允许阶段调用释放入口。
- [Buff](单位系统.md#buff)与技能在回合时机响应；流程不代替每个效果扣除持续时间。
- [伤害结算](伤害结算系统.md)完成单次伤害，流程根据结算后的状态推进胜负与行动。
- [棋盘与移动](棋盘与移动系统.md)将接入已有移动能力；其与施法、行动结束的协调仍需明确。

## 当前范围与后续边界

1v1 与 2v2 的操作方式、当前全局回合约定、击杀再动测试场景和未决时序见 [回合与对战实现记录](../../Implementation/Prototype/回合与对战实现.md)、[双打说明](../../../Prototype/DuoREADME.md)。不同演示的出手安排不直接等同于最终行动顺序规则。

后续重点是整体战斗流程、每个 slice 的边界与 Hook、资源消耗、额外行动、休息及不能行动等分支。血量、行动力、蓝量是否采用 ResourceAttribute 尚未决定。
