# 回合与战斗流程管理系统设计

> 状态：草案

## 1. 系统概述

讨论回合切换、单位行动资格和战斗阶段。当前采用统一的全局回合：所有单位完成一轮行动算一个回合。1v1 按固定顺序行动；2v2 中我方可自由选择队内出手顺序，敌方队内按固定顺序。两版均为原型规则，不代表最终行动排序方案已经确定。通用结算契约仍待讨论。

本文区分已确认约束、用户流程图所表达的草案，以及尚未确定的规则。文档整体继续保持“草案”状态。

### 1.1 设计目标

使战斗阶段和行动条件明确，方便验证流程推进及终止行为。

当前先为 HTML 原型明确可验证的规则，优先覆盖 Buff 管理、技能数据结算、数值管理和回合流程控制；详细规则分别在对应文档中维护。

当前已实现 Attribute、Buff 与 Skill TypeScript 原型，以及最小 CombatManager 阶段派发。技能已通过三个 Set 的单位组成接入公共 Hook。另有 [HTML 验证流程](../../../Prototype/README.md)：PrototypeBattle 负责固定 1v1 的我方行动、敌方行动、回合末和结束阶段；双方各行动一次后才调用 CombatManager.EndTurn。C++、通用施法调度和完整行动循环继续留待后续。

该验证流程的休息只跳过一次行动；直接技能后立即检查胜负，回合末则完成统一快照的所有 Hook 后再检查，允许同一轮持续伤害造成平局。界面自动推进仅代替点击操作，不改变结算顺序。这些是便于验证的原型规则，不代表下文所有草案分支已经实现。

另有独立的 [2v2 双打流程](../../../Prototype/DuoREADME.md)，实现位于 Combat/DuoBattle.ts。玩家可自由安排两名存活队友的出手顺序，每人每回合一次行动或休息；敌方存活单位随后依次行动，完成后才调用 CombatManager.EndTurn。倒下角色跳过行动与选目标；一方全部倒下才结束战斗，回合末仍完成整轮 Hook 后判断胜负。该流程验证友方目标、群攻、治疗驱毒、叠毒引爆等组合，不扩展为通用死亡或行动排序系统。

## 5. 核心执行流程

### 5.1 已确认约束

- 所有单位完成一轮行动计为一个全局回合；回合内单位依次行动。
- 当前 HTML 原型按固定顺序推进；该简化前提不扩展为最终排序机制的决策。
- “回合开始前”为全局回合开始前的 Hook 时机，用于 Buff 等 Model 的相关结算。
- “角色行动前”和“角色行动后”均为 Hook 时机。
- Buff 持续时间按全局回合计数，在全局回合结束时扣减；单位之间切换不扣减持续时间。具体生命周期规则见 [Buff 系统](../../Architecture/Subsystems/单位系统.md#buff)。
- 最终玩法允许特殊单位因 Buff 等原因在使用技能后移动；这项能力不纳入当前 HTML 原型。
- 当前 HTML 原型省略全部移动分支，不处理“进入前”和“进入后”。

### 5.2 结合统一回合定义的流程草案（省略移动）

图中包含初始化、战斗开始、回合开始前、确定下一个单位、能否行动、选择休息或使用技能、行动前、计算并施加效果、行动后及回合结束等节点。

图示的行动分支为：能行动时选择休息或技能，经过行动前处理、效果结算和行动后处理；不能行动时直接进入图中的“行动后”。该分支的准确语义仍待明确。

根据后续确认的统一回合定义，原图中“回合结束后直接选择下一个单位”的连线需要区分两个层级：单个单位结束的是单位行动阶段；所有单位完成一轮后，才结束全局回合。

用于后续讨论的基本循环为：全局回合开始前 Hook → 本回合内按固定顺序处理各单位行动阶段 → 本回合全部处理完毕 → 全局回合结束时扣减 Buff 持续时间 → 下一全局回合。

在图示的正常行动分支中，“行动前”和“行动后”分别对应已确认的“角色行动前”Hook 和“角色行动后”Hook，位于计算并施加效果的前后。

以上完整行动循环仍为草案。不能行动、行动被中断或角色死亡时是否触发角色行动前后 Hook，仍待确定。全局回合结束 OnTurnEnd 已在第一版 Buff 原型中实现：本回合中途施加的效果参与本回合末结算，持续 1 回合就在本回合末到期，顺序为该 Buff 的效果、扣时间、到期移除。
