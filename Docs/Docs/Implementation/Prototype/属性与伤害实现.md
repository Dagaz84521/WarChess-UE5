# 属性与伤害结算系统设计

> 状态：属性、Health 与 ADR-005 四阶段伤害已实现；护盾、分摊与复活仍待设计。
>
> 原型入口与运行方式见 [Prototype](../../../Prototype/README.md)，属性公式依据 [ADR-003](../../Architecture/Decisions/ADR-003-Buff改变Attribute的方式.md)，当前基础伤害公式与未决扩展的暂定约定见 [伤害结算实现](伤害结算实现.md)。正式伤害决策见 [ADR-005](../../Architecture/Decisions/ADR-005-伤害结算流程.md)。实现采用 TypeScript 普通类，不代表已确定 UE 对象类型。

## 1. 系统概述

当前实现 AttributeSet、Attribute、Modifier，以及 ADR-005 四阶段的 DamageCmd.CauseDamage。Health 表示剩余生命且禁止 Modifier，生命上限增益使用 MaxHealth。概率判定与单包死亡通知已接入，护盾、分摊与复活仍待后续设计。

### 1.1 设计目标

使数值来源和结算结果可解释，并支持新增规则及组合验证。

先明确 Health、MaxHealth、AttackPower、DefendPower 的逻辑结构，不依赖棋盘、位置或寻路。

### 1.2 职责范围

AttributeSet 管理 Attribute；每个 Attribute 以独立 GameplayTag 标识，包含 BaseValue、CurrentValue 和 Modifiers。Modifier 可表达固定值加成、百分比加成等计算类型。

### 1.3 非职责范围

BuffModel 的生效与失效由 [Buff 子系统](../../Architecture/Subsystems/单位系统.md#buff) 描述；技能玩法和冷却归 [SkillModel](../../Architecture/Subsystems/单位系统.md#技能)。属性模块不接管这些生命周期或玩法职责。

DamageCmd 负责暴击/格挡、计算、施加及死亡通知，读取概率属性并使用共享随机源；命中由技能层负责。公共虚方法统一定义在 AbstractModel，具体权限与结果见伤害结算实现。护盾、分摊与复活仍待设计。

## 2. 核心职责

| 对象或数据 | 职责 |
| --- | --- |
| AttributeSet | 管理本单位当前拥有的属性；子类显式注册，支持按标识查询、修改基础值，以及添加、按 Handle 移除 Modifier。 |
| Attribute | 保存基础值、最终值与作用于自身的修饰器集合。 |
| Modifier | 表达一项固定值、百分比等数值修正，不承担 Buff 的持续时间管理。 |

CurrentValue 根据 ADR-003 的公式计算：`CurrentValue = (BaseValue + ΣFlat) × (1 + ΣPercent)`。CurrentValue 对外只读，不能作为与基础值和修饰器无关的独立事实随意修改。BaseValue 通过明确的方法修改，触发立即重算。

已确定 Health 只表示剩余生命，不接收 Modifier，因此它的 BaseValue 与 CurrentValue 始终相等。DamageCmd 写入扣血后的基础值，立即反映到 CurrentValue；最大生命增益使用 MaxHealth 的 Modifier。

## 3. 核心对象与数据结构

### 3.1 属性范围与标识

| 属性 | 含义 | 标识约束 |
| --- | --- | --- |
| Health | 生命值 | 使用独立 GameplayTag。 |
| MaxHealth | 最大生命值 | 使用独立 GameplayTag。 |
| AttackPower | 攻击力 | 使用独立 GameplayTag。 |
| DefendPower | 防御力 | 使用独立 GameplayTag。 |

`PrototypeAttributeSet` 继承 `AttributeSet`，声明 Health、MaxHealth、AttackPower、DefendPower，以及暴击/格挡概率与倍率。基础生命和攻防默认为 0，概率/倍率默认值见 5.2。Health 注册时指定 SupportsModifiers=false，直接或经 AttributeSet 添加 Modifier 都会抛错。MaxHealth 接收 Modifier；本版未实现最大生命变化后的自动补血或生命裁剪。标识符集合还保留通用测试使用的 `Attribute.Attack`、`Attribute.Defense`，它们不属于 PrototypeAttributeSet。

定义标识符常量不代表所有 AttributeSet 自动拥有这些属性。子类调用受保护的 `RegisterAttribute` 声明自己的属性，基类为每次声明创建独立实例。

标识符采用带类型约束的字符串，通过 `CreateAttributeId` 创建。仅支持区分大小写的精确匹配，暂不实现 GameplayTag 层级匹配。拒绝空串和首尾空白，不做静默标准化。同一 Set 内重复声明直接抛错；不同 Set 的实例状态隔离。

### 3.2 Attribute 的逻辑字段

| 字段 | 含义 |
| --- | --- |
| BaseValue | 基础属性值。 |
| CurrentValue | 根据 BaseValue 与当前 Modifiers 计算得到的最终属性值。 |
| Modifiers | 当前作用于此 Attribute 的修饰器集合。 |

每个 Attribute 由自己的标识符标识。原型采用 `number` 保存数值，使用 Map 管理 Modifier；BaseValue、CurrentValue 通过只读 getter 暴露，不允许直接赋值绕过重算。具体 UE 类型仍待确定。

### 3.3 Modifier 与 Handle

Modifier 包含只读的 `Type` 和 `Value`，原型支持 `Flat` 与 `Percent` 两种类型；百分比用小数表达，`0.2` 表示 +20%。添加时保存不可变快照，避免调用方后续修改输入对象绕过重算。

每次添加生成独立、不透明的 symbol Handle，定位一次添加结果，不等同于属性标识符或 Buff 类型。相同 Modifier 的两次添加也有不同 Handle。Handle 只对持有该项的 Attribute 及其 AttributeSet 有效；移除后失效且不会复用，不支持序列化。来源追踪见 Buff 文档。

## 4. 对外接口与模块依赖

最小操作职责包括按 GameplayTag 查询 Attribute、向指定 Attribute 添加 Modifier，以及按追踪信息移除对应 Modifier。采用 Handle 时，添加结果需要能被来源 BuffModel 保留和定位。

原型接口如下：

| 接口 | 契约 |
| --- | --- |
| `RegisterAttribute(id, baseValue, options?)` | protected，供子类声明属性；可指定 SupportsModifiers=false，默认 true；重复标识符抛错。 |
| `GetAttribute(id)` | 返回对应 Attribute，缺失时为 undefined。 |
| `SetBaseValue(id, value)` | 修改基础值并立即重算；缺失属性抛错。 |
| `AddModifier(id, modifier)` | 成功后返回独立 Handle；缺失属性或无效输入抛错。 |
| `RemoveModifier(handle)` | 在本 Set 内查找并移除精确对应项，返回 boolean；无效、跨 Set 或重复移除返回 false。 |

单个 Attribute 也提供 `SetBaseValue(value)`、`AddModifier(modifier)`、`RemoveModifier(handle)`，与 Set 入口操作同一份状态。AttributeSet 当前遍历自己的 Attribute 查找 Handle，每个 Attribute 内通过 Map 定位，避免重复维护索引。跨 Attribute 的 Handle 不会误删其他项。

Unit 组成见 [Model 设计](../../Architecture/Mechanisms/Model机制.md)。Hook 的调用范围与时序在 [Hook 文档](../../Architecture/Mechanisms/Hook派发机制.md) 维护，属性模块不另建事件系统。

## 5. 核心执行流程

### 5.1 属性计算的职责表达

原型已实现以下计算流程：

```text
给定一个 Attribute：
    CurrentValue = (BaseValue + 固定值之和) × (1 + 百分比之和)

修改 BaseValue、添加或成功移除 Modifier 后：
    立即根据基础值和剩余 Modifier 重新计算 CurrentValue
    后续读取直接返回计算结果，不遍历 Buff
```

固定值先求和并加到 BaseValue，再乘以百分比之和加一。多个百分比相加，不逐项相乘；移除时从剩余项重算，不反向加减旧值。暂不增加其他计算类型。

### 5.2 Health 与 DamageCmd

Health 表示剩余生命且禁止 Modifier，MaxHealth 接收上限修正。CauseDamage 已按 ADR-005 接受 Direct / PercentMaxHealth，共用否定、替换、取整、实际扣血、溢出与死亡通知；Fixed 仍为预留，不接受旧请求。

概率属性为 CritChance / CritMultiplier / BlockChance / BlockMultiplier，默认 0 / 1.5 / 0 / 0.5。增加概率百分点使用 Flat Modifier，属性本身仍按 ADR-003 合并。命中由技能层 SkillHitExecutor 负责。

四阶段 Context、随机数、输入冻结和结果记录统一见 [伤害结算实现](伤害结算实现.md)。最小 HealingCmd 独立治疗存活单位，按当前 MaxHealth 限制新增生命，不复活、不重置已受伤害。

### 5.3 统一修正与否定

直接伤害的独立因子通过 AddModifier 收集，按 Type、Position、Independent 顺序相乘；两个 10% 减伤最终为 0.81。百分比伤害不接受通用乘数，取消/替换在施加阶段执行。零因子被拒绝，免疫和完全格挡须使用 Negated。

御势在 BeforeCalc 提交 0.5 因子，实际受到本包直接伤害后消耗；免疫与百分比伤害不消耗。旧固定减伤加百分比减伤及忽略开关方案不属于本次正式决策，不能用作当前实现的验收依据。

## 6. 扩展机制

属性通过独立标识区分，效果通过 Modifier 表达数值影响；新增规则时仍保持 BuffModel 或 SkillModel 的行为内聚。

自定义 AttributeSet 子类可以通过自定义标识符注册新属性，无需修改基类。其他修正类型或伤害类型留待后续，不预建通用注册表。

## 7. 约束与边界情况

原型采用 JavaScript number，拒绝非有限输入，不取整、不限制负值、不做上下限裁剪；保留浮点数语义。每次移除只影响对应 Handle 的一项，不影响其他来源。

Health 禁止 Modifier，MaxHealth 的 Modifier 重算不会重置已受到的伤害。DamageCmd 将扣血后的值限制为非负；普通 Attribute 的通用基础值接口仍不增加全局上下限规则。

伤害在统一出口取整并支持显式否定、替换与单包死亡通知；普通属性本身仍保留小数。护盾、复活及最大生命下降后的裁剪规则仍待设计。

## 8. 验证与测试

已编写自动化测试（运行方式见 Prototype README）：

- 验证子类声明、继承扩展、精确标识符查询、缺失与重复声明处理。
- 验证 ADR-003 示例：100 → 添加 +20 得 120 → 添加 +50% 得 180 → 移除 +20 得 150 → 移除 +50% 得 100。
- 验证多个百分比相加、修正类型添加顺序、基础值变化、负值与小数。
- 验证相同 Modifier 的独立 Handle、来源清理、跨属性与跨 Set 隔离、重复移除。
- 验证无效输入不修改状态、输入快照，以及只读接口的编译时约束。
- Damage 测试覆盖 Health 拒绝 Modifier、MaxHealth 修改与扣血独立、过量与零伤害、小数与无效输入、真实受击 Hook、条件 Buff 移除，以及带冷却技能造成伤害。

伤害与流水线测试覆盖 ADR 算例、直接/百分比形式、最低伤害、否定、毒疗、实际扣血、死亡顺序、概率重放、阶段权限、FIFO 队列和多段中断；既有属性、Buff、技能与对战测试继续运行。具体命令和浏览器验证见 [Prototype README](../../../Prototype/README.md)。

技能内容案例见 [火球术](../../Examples/01-实现一个火球术.md)，不能把案例当作已经确定的伤害公式。
