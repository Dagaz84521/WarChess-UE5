# 技能管理与 SkillModel 系统设计

> 状态：技能、回合冷却与 CauseDamage 示例已实现；完整施法流程待设计。
>
> 代码位于 [Prototype/Model/Skill](../../../Prototype/Model/Skill)，运行方式见 [Prototype README](../../../Prototype/README.md)。

## 1. 核心职责

| 对象 | 职责 |
| --- | --- |
| SkillSet | 管理一个单位拥有的 SkillModel，支持添加、按标识查找、移除和快照遍历。 |
| SkillModel | 继承 AbstractModel，以 OnPlay 定义本技能的效果，并可响应公共 Hook。 |
| 具体 CMD | 执行效果引起的状态变更；增加 Buff 调用 BuffCmd，造成伤害调用 DamageCmd。 |
| Unit | 持有 AttributeSet、BuffSet、SkillSet，提供公共 Model 快照及有效性判断。 |

SkillSet 不按技能名称编写效果分支，不执行 OnPlay，也不集中管理技能冷却。SkillModel 的玩法保持 Code-First；技能不复制 Buff 或伤害的结算实现。

## 2. SkillModel 与释放入口

SkillModel 构造时绑定只读 Owner 和 SkillId。SkillId 使用 CreateSkillId 创建，采用区分大小写的精确字符串匹配，拒绝空串及首尾空白。

本版释放契约为 OnPlay(context): void，context 是 SkillPlayContext，包含只读 Target。施法者直接使用技能的 Owner，避免由调用方重复传入施法者。这是最小单目标入口，尚未定义多目标、阵营限制、目标选择、范围与资源消耗。

具体技能必须实现 OnPlay。正常释放通过 Play(context): boolean，检查角色仍持有本实例、未在释放中、冷却已结束，然后调用 OnPlay；成功返回后进入冷却。不可释放返回 false；效果异常继续抛出，不进入冷却。直接调用 OnPlay 仅执行效果，绕过这些检查，调用方不应把它作为正常释放入口。行动资格与完整释放调度仍待明确。

SkillModel 继承公共 OnTurnEnd、AfterDamageTaken、AfterBuffApplied、AfterBuffStackChanged、AfterBuffRemoved；新增必要时机时扩展 AbstractModel 与实际派发。OnPlay 属于技能自身入口，保留在 SkillModel。

## 3. SkillSet 的管理规则

| 接口 | 契约 |
| --- | --- |
| AddSkill(skill) | 技能 Owner 必须是本 Set 所属单位；重复标识抛错，成功返回传入实例。 |
| GetSkill(id) | 返回拥有的技能，缺失返回 undefined。 |
| HasSkill(id) | 判断是否拥有该标识的技能。 |
| RemoveSkill(id) | 移除该技能；缺失或重复移除返回 false。 |
| GetSnapshot() / 迭代 | 返回只读快照，顺序为加入顺序。 |

同一单位内同标识技能不重复添加，不同单位可以分别持有同标识的独立实例。技能 Owner 不允许直接改写，不允许把一个实例加入其他单位。

移除技能只改变技能集合，停止它后续的 Hook 参与；已经通过 BuffCmd 施加的 Buff 仍由 BuffCmd 和各 Buff 自己管理。技能是否具有被动效果及专属清理生命周期，留待出现具体需求后确定。

## 4. 公共 Hook 派发

Unit.GetModelsSnapshot 收集 Buff 与技能，顺序为 Buff 加入顺序、技能加入顺序。Unit.IsModelActive 分别判断 Buff 的 Active 与集合归属、技能的集合归属；不把技能冷却等同于失去 Hook 参与资格。

CombatManager 的全局回合结束、DamageCmd 扣血后的受击 Hook，以及 BuffCmd 的完成后规则 Hook，都通过公共派发到达有效技能。阶段开始时统一拍快照，每次调用前检查归属，期间移除的实例跳过，新增或同标识替换的实例等待下一次阶段。

目标单位的 Buff 规则事件向该单位的 Buff 和技能派发，不隐式扩大成全战场监听。

## 5. 已实现示例

AttackPowerUpSkill 的 OnPlay 调用 BuffCmd.Apply，给 context.Target 添加现有 AttackPowerBuff，并把技能 Owner 作为 Source。

这个示例沿用已经实现的效果：每层 +10 攻击力，最多 6 层，默认 3 回合。不同角色施加时合并为同一 Buff 实例，重复施加刷新时间；这些规则全部由 BuffCmd 及 BuffModel 执行，技能不重复实现。

DirectDamageSkill 的 OnPlay 通过 SkillHitExecutor 确认命中，再提交 `{ Kind: "Direct", Power: this.Power }`，默认 Power=20、冷却 2 回合。基础伤害为 P×A/max(1,D)，暴击与格挡读取当前概率属性并使用战斗随机源。

引毒使用 `{ Kind: "PercentMaxHealth", Ratio: stacks / 24 }`，确认命中后移除毒蚀并结算百分比伤害。毒蚀 tick 每层比例为 1/32；这些是演示数值。百分比不参与暴击、格挡或通用乘数，仍共用施加出口。Fixed 按 [ADR-005](../../Architecture/Decisions/ADR-005-伤害结算流程.md) 保持预留，当前明确拒绝旧请求，细节见 [伤害结算实现](伤害结算实现.md)。

SkillHitExecutor 支持 Once / PerHit 命中策略、未命中停止该目标、每段 on-hit、段序号与多目标顺序。每段前后检查存活，攻击者死亡停止后续段，目标死亡只跳过该目标。状态效果可以单独使用 Confirm，不创建虚假的伤害请求。

## 6. 验证

15 项技能测试覆盖：

- 拥有、查找、直接 OnPlay，以及 Owner 约束、重复标识和跨单位隔离。
- 两个角色通过技能向同一目标施加 Buff，验证实际属性、叠层与刷新。
- 技能通过实际运行时派发收到回合、受击、Buff 施加、叠层与移除通知。
- 技能移除、同标识替换、跨单位新增与 Hook 中修改集合。
- 移除技能不误删已经施加的 Buff，以及只读接口的类型检查。
- 成功后进入冷却、冷却中拒绝释放、全局回合结束恢复、跨实例隔离、失败不进冷却、递归释放保护与手动重置。

伤害与流水线测试覆盖 Direct / PercentMaxHealth、ADR 算例、概率、输入冻结、队列、多段中断及技能冷却。双打集成测试覆盖目标、群攻、破甲、百分比毒爆、治疗与击杀再动，浏览器检查覆盖实际离线页面。技能表与运行方式见 [双打说明](../../../Prototype/DuoREADME.md) 和 Prototype README。

## 7. 冷却规则

SkillOptions.Cooldown 配置非负整数回合数，默认 0。Cooldown 对外只读，RemainingCooldown 初始为 0。成功 Play 后设为 Cooldown；失败不开始冷却，已完成的外部 CMD 不自动回滚。

每个全局回合结束减 1，包括释放所在回合结束；冷却为 2 的技能在成功释放后为 2，本回合末为 1，下一回合末为 0。技能自己通过 OnTurnEnd 推进，SkillSet 和 CombatManager 不额外扣减。具体技能重写 OnTurnEnd 时需调用 super.OnTurnEnd(context)，保留基类计数。

技能提供 StartCooldown、ReduceCooldown、ResetCooldown，RemainingCooldown 不允许直接赋值。CanPlay 同时检查冷却、持有关系和递归释放保护；IsOnCooldown 仅表达冷却是否大于 0。当前不按死亡、资源或阵营判断释放资格。

双打流程在调用 Play 之前额外校验存活、每轮行动次数、己方行动者与目标阵营；引毒要求目标持有毒蚀。横扫的具体 Skill 通过注入的敌方列表分别调用 CauseDamage，没有改变公共 SkillPlayContext 的单目标字段。回春诀通过 BuffCmd 与最小 HealingCmd 执行效果。这些是原型玩法层的限制，通用目标与资源契约仍待设计。

- 是否引入 SkillCmd、更完整的释放前校验、效果失败的跨 CMD 回滚及复杂嵌套施放。
