# Prototype 伤害结算实现

> 更新日期：2026-10-23。已按 [ADR-005](../../Architecture/Decisions/ADR-005-伤害结算流程.md)迁移直接伤害、百分比伤害、四阶段 Hook、随机判定和统一扣血。未决扩展的暂定行为在文末单列，不表示完整战斗框架已实现。

## 入口与请求

    DamageCmd.CauseDamage(target, source, { Kind: "Direct", Power: 20 });
    DamageCmd.CauseDamage(target, source, { Kind: "PercentMaxHealth", Ratio: stacks / 32 },
      new FDamageContext({ SourceEffect: poisonBuff, Tags: ["Poison"], bCanAttributeKill: false }));

[请求类型](../../../Prototype/Combat/FDamageRequest.ts)只允许 Direct 与 PercentMaxHealth。Direct 可选 AttackAttribute / DefenseAttribute，默认使用来源 AttackPower 与目标 DefendPower；百分比读取计算时目标的当前 MaxHealth。Fixed 属于预留，不接受旧 Fixed 或 Power 请求。源单位允许为空的环境伤害可使用百分比形式。

两类都要求目标有禁止 Modifier 的有限非负 Health；Direct 要求来源及攻防属性，百分比要求有限非负 MaxHealth。输入请求与元数据复制冻结；来源对象与 SourceEffect 保留身份引用。

命中属于 [SkillHitExecutor](../../../Prototype/Model/Skill/SkillHitExecutor.ts)，不在 DamageCmd 内。技能先确认段，再调用统一伤害入口；状态效果可单独确认命中并施加 Buff。

## 阶段与权限

| 检查点 | 可以修改 | 完成后 |
| --- | --- | --- |
| BeforeCrit | Parameters.Chance、Multiplier、Forced、Cannot；提交未来计算因子 | 参数冻结，判定结果冻结 |
| AfterCrit | 提交未来计算因子、入队后续命令 | 不能回写暴击结果 |
| BeforeBlock | 对应格挡参数及 Complete 完全格挡标志 | 参数冻结，判定结果冻结 |
| AfterBlock | 提交未来计算因子、入队后续命令 | 不能回写暴击或格挡 |
| BeforeCalc | Inputs.Attack / Defense；Direct 的 AddModifier | 输入冻结，公式与乘数计算完成 |
| AfterCalc | 准备后续施加量、否定、替换或排队命令 | 计算结果只读，不再接受乘数 |
| BeforeApply | Parameters.Amount；Negate(reason)；ReplaceWithHealing(amount) | 施加参数冻结，单次生命提交 |
| AfterApply | 只读完整结果、入队后续命令 | 不回写当前结果 |
| OnDeath | 本包致死时通知目标 Model，可入队后续命令 | 在 AfterApply 之后、反应出队之前 |

百分比跳过暴击、格挡及其 Hook，Outcomes 为 null；保留 BeforeCalc / AfterCalc 与统一施加阶段。通用乘数提交会报错；只调整其不使用的攻防输入不改变百分比公式。

每个检查点对参与单位统一拍 Model 快照，稳定按来源、目标顺序调用，每单位 Buff 先于 Skill。自伤不重复派发同一 Model；派发时移除的对象跳过，新增对象从下一检查点参与。参数在阶段结束后冻结，Context 外壳、请求、已发布判定和结果都只读，保存的回调在阶段结束后拒绝调用。

## 公式与数值规则

    Direct = Power × max(0, Attack) / max(1, Defense)
             × CritMultiplier × BlockMultiplier
             × ΠType × ΠPosition × ΠIndependent
    PercentMaxHealth = current MaxHealth × Ratio
    Amount = floor(RawAmount)，正数基础伤害最低 1
    RemainingHealth = max(0, PreviousHealth - Amount)
    ActualDamage = PreviousHealth - RemainingHealth
    Overkill = max(0, Amount - PreviousHealth)

运算使用 JavaScript number（双精度），计算基础值时先将较大的乘数除以防御，以降低不必要的中间溢出。非有限值在本包生命提交前拒绝。

属性内增益遵循 ADR-003，独立伤害因子逐项相乘。两个 10% 独立减伤得到 0.81。完全免疫或完全格挡使用 Negated，不能提交零因子；Power / Attack / Ratio 为零时也明确标记 ZeroInput，最终为零，最低伤害不覆盖否定。

BeforeApply 可修正施加量以实现保留 1 HP；无标志地将施加量设为零会报错，应显式 Negate。首个否定/替换决定生效，其后的规则不能取消已成立的否定。

## 概率与随机数

原型属性新增 CritChance、CritMultiplier、BlockChance、BlockMultiplier，默认分别为 0、1.5、0、0.5。概率用小数表示，增加百分点使用 Flat 属性 Modifier。Before 检查点可以调整本次概率，限制在 [0,1] 后取样；Cannot 优先于 Forced，且已成立的 Cannot 不能被后续 Hook 清除。

CombatManager(units, seed = 1) 给所有单位绑定同一 [BattleRuntime](../../../Prototype/Combat/BattleRuntime.ts)。每个适用的 Direct 包固定依次消耗暴击和格挡两个样本，强制结果或 0 / 1 概率也消耗；百分比不消耗。相同种子、输入和调用顺序产生相同结果。

ExpectedDamage 是纯数值函数，接收概率、倍率和已知因子，按四种结果分别取整后加权；不会派发 Model Hook、不会消耗战斗随机数。它假设调用方提供的两个概率独立，不负责推导任意条件 Hook 的联合分布。

## 否定、毒疗与受伤事件

[PoisonHealBuff](../../../Prototype/Model/Buff/Examples/PoisonHealBuff.ts)在 BeforeApply 识别 Poison 标签，取消本次扣血并排队恢复当前最大生命的 1/8。治疗是独立 HealingCmd 命令，不复活、不超过当前 MaxHealth；满血或零治疗不会恢复被取消的伤害。

AfterApply 对正常、零输入、免疫和替换的包均执行。只有 ActualDamage > 0 才通知目标 AfterDamageTaken 与来源 AfterCauseDamage。正生命归零、有来源且 bCanAttributeKill=true 时派发来源 OnKill，然后通知目标 OnDeath。死亡在扣血后立即可观察，事后治疗不能撤销。

已死亡目标返回 InvalidTarget，不执行伤害 Hook、不消耗判定随机数、不重复通知死亡。结果区分 Applied、Negated、Replaced、InvalidTarget，并记录 Reason、原始值、取整值、实际扣血、溢出和生命前后值。

[御势](../../../Prototype/Model/Buff/Examples/BattleWardBuff.ts)在 BeforeCalc 对自身承受的 Direct 提交 0.5 独立因子，在该包实际扣血后移除；免疫或百分比伤害不会消耗。暴击破甲示例只修改本次 Inputs.Defense，不改变单位属性。

## 反应队列与诊断

Hook 使用 EnqueueDamage / EnqueueHealing，当前包的 AfterApply 与 OnDeath 完成后，按提交顺序 FIFO 执行；同一运行时的直接嵌套 CauseDamage 会报错。替换治疗在作出决定时入队，因此与其他反应具有稳定的提交顺序。

每个后续伤害保留 ParentId / RootId，在执行前重新检查目标。默认最大深度 32、最大队列长度与执行次数 256，防止递归及横向无限扩张。异常清除剩余队列并释放运行时；已完成的外部状态变更和生命提交不回滚，不能自动重试整个技能。

Runtime.DamageLog 保存不可变结果，Breakdown 记录检查点、计算值、判定及随机样本。日志中的单位引用用于进程内诊断，持久化回放格式尚未实现。

## 内容与验证

毒蚀每层为目标当前最大生命的 1/32，引毒每层为 1/24，属于演示数值。直接技能威力继续使用 20 / 16。技能层支持单次/逐段命中、多目标固定顺序、逐段取整、目标死亡中断以及反应杀死攻击者后的中断。

证据见 [伤害测试](../../../Prototype/Combat/Tests/Damage.test.ts)、[流水线测试](../../../Prototype/Combat/Tests/DamagePipeline.test.ts)、[1v1 集成测试](../../../Prototype/Combat/Tests/PrototypeBattle.test.ts)、[双打集成测试](../../../Prototype/Combat/Tests/DuoBattle.test.ts)与 [浏览器检查](../../../Prototype/Scripts/check-ui.mjs)。运行方式及回退点见 [Prototype README](../../../Prototype/README.md)。

## 未决项的原型约定

- 同检查点没有通用优先级注册表；稳定遍历，首个取消/替换决定生效。正式优先级仍依赖 ADR-004。
- 队列中的已确认反应允许来源死亡后继续，目标无效时跳过；需要命中的反应应先由技能层确认。
- Fixed、护盾、分摊、复活、通用治疗 Hook 与持久化回放仍未实现。
- 独立 DamagePrototype 保留旧演示，不在本次迁移范围内。
