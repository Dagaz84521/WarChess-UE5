# 方格移动原型实现记录

> 更新日期：2026-10-28。TypeScript / HTML 演示，不代表六边形 C++ 迁移或 UE 集成已经完成。

## 当前能力

依据 [ADR-007](../../Architecture/Decisions/ADR-007-移动系统与寻路算法解耦.md)，实现单角色、四邻接方格、预算受限 Dijkstra、可复用最短路径树、范围显示、路径预览与逐格执行。运行入口及规则见 [MovementREADME](../../../Prototype/MovementREADME.md)。

`MovementState` 在本演示中充当最小单位权威状态；没有新建完整 CombatState，也没有把独立移动演示接进现有 1v1 / 2v2 战斗。Board 提供拓扑和地形，单单位占位直接由 State 的位置决定，不再保存第二份占位状态。

调用关系：

```text
页面 → MoveResolver → MoveContext（Input + CachedRange）
             ↓ 缓存缺失 / 状态或地形版本改变
       SearchRange(Start, Budget, EdgeProvider)
             ↓                     ↑
       MovementRangeResult      MoveRule ← Board + Input
        ├─ GetMoveRange(CanStop) → 可选终点
        └─ BuildPath(Target)     → 完整路径
                                      ↓
                           MovementDemo 逐格执行器
                                      ↓
                           状态提交 → 离开 / 进入事件
```

## 结果和缓存

`MovementRangeResult<CellId>` 包含 `Start`、只读类型的 `CostMap`、`PreviousMap`。起点费用为 0，不保存前驱；查询起点路径返回单元素路径。起点也是可停留节点，页面将它从“可选终点”数量排除，原地指令按无操作处理，不扣费、不产生事件。

Dijkstra 使用最小堆，以实际累计费用优先、入队顺序处理平局；只在更低费用时更新前驱。方格邻接顺序固定为北、东、南、西。算法允许非负整数费用；当前执行规则实际只产生正整数 1 / 2。预算外节点不进入结果，不会把单目标提前结束的搜索结果当成完整范围。

MoveResolver 持有当前单位的一个 MoveContext。其 `Input` 是不可变快照，缓存同时记录 BoardRevision。演示内所有位置、预算、飞行状态、回合补给写入均递增 StateRevision，地形变化递增 BoardRevision；两者任一不匹配则重新构建整棵树。Resolver 实例绑定同一个 Board 和 State，第一版不支持更换棋盘对象或多单位缓存。

范围查询、多个目标的路径恢复、MoveCommand 共用 `EnsureContext`。即使先提交移动指令，也先生成完整树，后续范围查询无需再搜索；有效结果中目标非法时直接拒绝。执行完成后页面查询新位置的范围，会新增一次合理的搜索。

## 逐格事件约定

MoveResolver 只输出包含路径、总 Cost、状态版本和棋盘版本的 MoveAction。`MovementDemo.BeginMove` 保留计划；实际执行发生在 `Step()`。计时器仅决定何时调用 Step，不负责规则或费用计算。

每一步的固定顺序：

1. 核对棋盘版本、预期状态版本和当前相邻边；不匹配则终止剩余移动，保留已经完成的步数。
2. 一次提交角色新位置及本步预算扣除。
3. 生成 `LeaveCell` 快照，Cell 为旧格。
4. 生成 `EnterCell` 快照，Cell 为新格。

两条事件均在状态提交后生成，`PositionAfter` 指向新格，`RemainingBudget` 是同一个扣费后的值。`LeaveCell` 表示离开事实，不能解释为可取消的“移动之前”检查点。

| 事件字段 | 语义 |
| --- | --- |
| Sequence / MoveId | 全局递增事件编号 / 本次移动编号 |
| Type / Cell | LeaveCell 或 EnterCell / 该通知对应的格子 |
| UnitId / From / To | 当前角色及本步起止格 |
| Step / StepCost | 本次移动内从 1 开始的步号 / 本步费用 |
| RemainingBudget / PositionAfter | 提交后的预算和位置 |

事件对象与每步返回数组冻结；历史记录保存数值、字符串快照，不持有可变单位引用。清空显示记录不改变角色状态，也不重置事件编号。筛选只影响展示，不改变实际记录。

这里为后续 Hook 提供真实事件及其观测时点，尚无 Model 回调、规则拦截或事件引发的反应。后续若增加 BeforeMove / BeforeLeave、陷阱或中断，应明确它们在状态提交前后的位置及失败处理；不能把当前事后日志直接当作允许改写或取消移动的接口。

## 演示边界与验证

设置预算会同时设置当前值与后续回合恢复上限；切换飞行保留剩余值。飞行单位允许河上悬停，落在河流时拒绝切回地面；岩石对两种移动方式都阻挡。配置和新回合按钮在执行中禁用，重置可以直接丢弃当前演示并取消计时器。这里没有实现通用战斗回合或通用可取消 Action。

核心测试见 [Movement.test.ts](../../../Prototype/Movement/Tests/Movement.test.ts)，覆盖加权松弛、稳定前驱、可经过不可停留的通用结果、地面 / 飞行费用、桥梁和河流、一次搜索多次复用、缓存失效、过期计划拒绝、事件顺序、只读快照、零预算及原地目标。

浏览器检查见 [check-movement-ui.mjs](../../../Prototype/Scripts/check-movement-ui.mjs)，覆盖真实自动执行、暂停 / 单步、事件筛选、切换与配置约束、键盘、执行中重置、离线导航，以及 1440 / 768 / 375 三种宽度。当前验证结果应以运行这些检查的输出为准。

六边形实现复用、C++ / UObject、多个单位与阵营占位、Buff、可编辑路径、正式 Hook 派发及 UE 表现仍不在本原型范围内。已有迁移计划继续见 [六边形网格与 A* 迁移清单](六边形网格与AStar迁移清单.md)。
