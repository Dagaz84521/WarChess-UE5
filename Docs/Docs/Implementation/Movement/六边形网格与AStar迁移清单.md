## 2. 渐进迁移步骤

| 阶段 | 最小改动 | 完成标准 | 进展 |
| --- | --- | --- | --- |
| 0：保留基准 | 固定小地图、起点、预算及规则，记录现有路径和总费用 | 可重复比较行为，不以截图代替费用校验 | 待进行 |
| 1：封装棋盘 | 提供 CellId、只读事实和邻接；保留六边形内部表示 | 调用侧不需要计算六边形坐标；邻接顺序明确 | 待进行 |
| 2：抽离规则 | 把通行与 Cost 分支移至 MoveRule，分离 CanStop | 单目标合法性与最低费用保持；规则不修改状态 | 待进行 |
| 3：生成最短路径树 | 以预算受限 Dijkstra 搜索，按需要复用已有队列、松弛与前驱组件 | 预算内节点均有最低 Cost 和有效前驱，无单目标提前结束 | 待进行 |
| 4：实现结果操作 | 在同一 Result 上提供 GetMoveRange 与 BuildPath | 范围按停留规则筛选；多个目标只恢复路径，不增加搜索调用 | 待进行 |
| 5：统一查询与指令 | Resolver 共用结果获取步骤，Context 缓存完整树 | 无缓存指令先建树，后续查询复用同树；无 A* 回退分支 | 待进行 |
| 6：接入失效 | 建立战斗作用域缓存键与统一版本推进 | 依赖变化不复用旧结果，解析不写权威状态 | 待进行 |

已有 A* 保留为独立单目标能力，可按需要适配统一边接口与外部估价；它不阻塞树结果主流程，也不作为阶段 5 的默认回退。可复用组件以实际源码核对为准，不为共享强制重写或合并两种算法。

## 3. 重点审查项

- A* 是否直接读格子 Actor、地形枚举、单位阵营或 Buff；将这些读取移到规则适配侧。
- 启发函数是否写死六边形距离乘单位费用；检查该费用下界是否仍成立。
- 范围搜索是否错误保留“发现 / 取出目标后结束”；范围必须覆盖预算内所有可达节点。
- MovementRangeResult 是否完整表达 Start、CostMap 与 PreviousMap；可经过但不可停留节点是否保留在树中。
- GetMoveRange / BuildPath 是否只消费已有结果；缓存缺失时的 Query 与 Command 是否统一建树，而非下令时切换 A*。
- 独立 A* 的部分 CostMap 是否误写入树缓存；它与完整树保持清晰完整性边界。
- 队列同费用项是否有稳定顺序；是否依赖哈希容器迭代顺序。
- 零费用边、不可达目标、起点目标、前驱缺失和费用溢出如何处理。
- 位置与占位是否存在双写，规则读取的版本是否与状态一致。
- 搜索后到提交前能否识别过期计划；不在本阶段设计逐格执行器。

## 4. 验证记录模板

| 项目 | 需要记录的证据 |
| --- | --- |
| 输入 | 棋盘版本 / 拓扑、起点、目标、预算、移动能力、占位和规则参数 |
| 结果 | 树中 Start、各节点最低 Cost 与前驱；GetMoveRange 终点集合、BuildPath 路径及失败原因 |
| 算法比较 | 完整树与已有独立 A* 的目标最低费用对照；等费用路径形状可不同，同一树的预览与指令路径一致 |
| 缓存 | 命中 / 失效原因、树搜索调用次数；先指令后查询、一次查询后恢复多个目标都只建树一次 |
| 一致性 | 查询前后权威状态对比，位置与占位视图一致性 |
| 性能 | 地图规模、预算、扩展节点、耗时和内存；确认实测后再设优化目标 |
| 实现证据 | 实际源码、测试位置与运行结果，不预填通过状态 |

基础案例见 [地形规则案例](../../Examples/03-扩展一种地形规则.md)。后续若增加第二种拓扑，可先使用最小邻接测试替身，不要求第二套正式关卡。
